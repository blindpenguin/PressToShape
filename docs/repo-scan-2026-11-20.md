## Checked and found safe

- **Atomic writes** (project save, settings store, code index): genuine write-temp-then-rename, stale temps cleaned, no attacker-controlled temp paths.
- **Untrusted input**: project files are non-polymorphic JSON with depth/size caps and finite-coordinate guards; recent-files and settings JSON are validated element-by-element; SVG export escapes through `XmlWriter` (`CheckCharacters`) with exact XML 1.0 character filtering.
- **XML/XXE**: `XamlReader` sets `DtdProcessing.Prohibit`, `XmlResolver = null`, with char/depth caps; recursion and cycles in parsers are depth- or visited-set-bounded.
- **Path handling**: index-relative paths go through `IndexPath.Normalize` (rejects rooted, drive-letter, `..` segments); `XamlWorld.Combine` rejects escaping includes.
- **Threading**: App UI code is UI-thread-only (no `Task.Run` races); Core is immutable records with a single owner-scoped mutable history object; the CodeIndex pipeline is sequential.
- **Geometry math** in Core: rotation conventions, boolean operations, curve fitting, rounded-rect radii consistency between hit-test, render and SVG export — all re-derived and correct.
- **Undo/redo reentrancy**: `CanUndo/CanRedo/JumpToStep` gated on `!IsDragInProgress`; async commands disallow concurrent execution.
- **Disposal/unsubscribe in views**: handlers detached consistently (exceptions noted in findings 2 and 11); render contexts and streams scoped with `using`.
- **Event subscriptions on app-lifetime objects**: `Localizer.LanguageChanged`, `_state.PropertyChanged` etc. only on documented app-lifetime holders; ring menu slots dispose their `CanExecuteChanged` subscriptions; repeated `Rebuild` always unsubscribes the previous slot set.

## Bottom line

A very well-kept codebase — clean build, fully green test suite, disciplined file/async handling. Fix first: the Layers-panel text mislabel (#1, user-visible bug), then the missing PR/push CI workflow (#7).
