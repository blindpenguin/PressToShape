# Tasks Document

Notes for every task:
- Requirement IDs (`R3.2` is Requirement 3, criterion 2) refer to `requirements.md`. Component names refer to `design.md`.
- Core code goes in `src/PressToShape.Core/IO/` (namespace `PressToShape.Core.IO`, public types with XML docs, no Avalonia, no `ILocalizer`, no file system access). App code goes in `src/PressToShape.App`. Tests go in `tests/PressToShape.Core.Tests` and `tests/PressToShape.App.Tests`. Do not change the heads or add any NuGet package (ask the owner if one seems needed). Do not add Avalonia.Headless.
- Follow `.claude/rules/`: compiled bindings with `x:DataType`, no Avalonia types in view models or `Workspace/`, one type per file, `internal` types in App, no hardcoded colors in views, avoid the word "kind" when "type" works. Keep the build warning-free (warnings are errors).
- Translatable texts: `ILocalizer.T("English")` in C#, `{loc:T 'English'}` in XAML. Every new text goes into `Translations/de.po` in the same task, because `TranslationConsistencyTests` fail on missing or obsolete entries. Texts with placeholders use `string.Format(localizer.Culture, localizer.T("... {0}"), ...)` and keep the placeholders in the translation.
- Tests: xUnit, `Method_Scenario_Expected`, arrange/act/assert, deterministic, no real dialogs or network. Use fakes. Real files only in a temp folder like `SettingsStoreTests`. Existing tests that break because of a task are updated in that task. Search `.spec-workflow/specs/*/Implementation Logs/` before writing code.
- If anything is unclear or the design does not work, stop and ask the owner. Do not guess.
- Build and test: `dotnet build src/PressToShape.Desktop`, `dotnet test`, and `dotnet format --verify-no-changes`.
- Do not commit unless the owner asks.
