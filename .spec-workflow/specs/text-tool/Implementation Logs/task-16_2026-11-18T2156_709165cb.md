# Implementation Log: Task 16

**Summary:** On-canvas text editing. New TextEditorControl (Canvas with a borderless TextBox in a theme-colored frame, styled by TextBox.textEditor in Controls.axaml, touch MinHeight override) placed over the canvas: shows the edited text at its screen box with font, size, weight, style, spacing, alignment, wrap (area) and rotation, takes the focus after the first layout pass, writes typing back via EditedText, Escape and focus loss to another control run the commit command. CanvasAreaViewModel.Text.cs exposes IsEditingText, EditedText (set = draft content + measured point-text box), EditedTextShape, EditedTextLineHeight and CommitTextEditCommand; the view returns focus to the canvas when editing ends. TextOperations.Fit added to Core (shared by ApplyLayout and the editor). TextFonts now falls back to the plain name when the bundled Inter is not registered. ScreenText gained Alignment/IsArea. Lesson: marking keys Handled in the control blocks text input on X11, so only Escape is handled; the desktop shell already skips tool/edit shortcuts while a TextBox has focus. Verified in the real app on Linux/Skia: click creates a point text, typing grows the box, Escape commits and the canvas draws it exactly where the editor was, an area text wraps in the dragged box. Not checked: IME, soft keyboard (task 20), rotated editing, Undo while editing by menu.
