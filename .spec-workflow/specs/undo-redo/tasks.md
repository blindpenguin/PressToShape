# Tasks Document

Notes for every task:
- Requirement IDs (`R2.3` is Requirement 2, criterion 3) refer to `requirements.md`. Component names refer to `design.md`.
- Core code goes in `src/PressToShape.Core/History/` (namespace `PressToShape.Core.History`, public types with XML docs, no Avalonia, no `ILocalizer`). App code goes in `src/PressToShape.App`, tests in `tests/PressToShape.Core.Tests` and `tests/PressToShape.App.Tests`. Do not change the heads or add any NuGet package (ask the owner if one seems needed). Do not add Avalonia.Headless.
- Follow `.claude/rules/` (`csharp.md`, `avalonia-mvvm.md`, `localization.md`, `testing-and-quality.md`): compiled bindings with `x:DataType`, no Avalonia types in view models or `Workspace/`, one type per file, `internal` types in App, no hardcoded colors in views, avoid the word "kind" when "type" works. Keep the build warning-free (warnings are errors).
- Translatable texts: `ILocalizer.T("English")` in C#, `Localizer.N("English")` in data tables, `{loc:T 'English'}` in XAML. Every new text goes into `Translations/de.po` in the same task, and removed texts are removed from it, because `TranslationConsistencyTests` fail on missing or obsolete entries.
- Tests: xUnit, `Method_Scenario_Expected`, arrange/act/assert, deterministic, no real dialogs. Existing tests that break because of a task are updated in that task. Search `.spec-workflow/specs/*/Implementation Logs/` before writing code.
- If anything is unclear or the design does not work, stop and ask the owner. Do not guess. If a task cannot build without another one, say so and do them together, as in earlier specs, and log them separately.
- Build and test: `dotnet build src/PressToShape.Desktop`, `dotnet test`, and `dotnet format --verify-no-changes`.
- Do not commit unless the owner asks.
