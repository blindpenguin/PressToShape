# Tasks Document

Notes for every task:
- Requirement IDs (`R3.2` is Requirement 3, criterion 2) refer to `requirements.md`. Component names refer to `design.md`.
- All code goes in `src/PressToShape.App`, tests in `tests/PressToShape.App.Tests`. Do not change `PressToShape.Core`, the heads or any NuGet reference (ask the owner if one seems needed). Do not add Avalonia.Headless.
- Follow `.claude/rules/` (`csharp.md`, `avalonia-mvvm.md`, `localization.md`, `testing-and-quality.md`): compiled bindings with `x:DataType`, no Avalonia types in view models or `Workspace/`, one type per file, `internal` types, no hardcoded colors in views, avoid the word "kind" when "type" works. Keep the build warning-free (warnings are errors).
- Translatable texts: `ILocalizer.T("English")` in C#, `{loc:T 'English'}` in XAML. Every new text goes into `Translations/de.po` in the same task, because `TranslationConsistencyTests` fail on missing or obsolete entries.
- Tests: xUnit, `Method_Scenario_Expected`, arrange/act/assert, deterministic. Existing tests that break because of a task are updated in that task. Search `.spec-workflow/specs/*/Implementation Logs/` before writing code.
- View changes never touch the document, the history or the dirty state (R1.4). Production code must keep following the rule that only `EditorState` assigns the document.
- If anything is unclear or the design does not work, stop and ask the owner. Do not guess. If a task cannot build without another one, say so and do them together, and log them separately.
- For manual runs read the memory notes about window placement: move the app window to the right screen after launch and re-read its position before each batch of input.
- Build and test: `dotnet build src/PressToShape.Desktop`, `dotnet test`, and `dotnet format --verify-no-changes`.
- Do not commit unless the owner asks.
