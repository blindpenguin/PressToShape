# Tasks Document

Notes for every task:
- Requirement IDs (`R5.4` is Requirement 5, criterion 4) refer to `requirements.md`. Component names refer to `design.md`.
- Core code goes in `src/PressToShape.Core` (public types with XML docs, no Avalonia, no `ILocalizer`), App code in `src/PressToShape.App`, tests in `tests/PressToShape.Core.Tests` and `tests/PressToShape.App.Tests`. The only new package is `Avalonia.Controls.ColorPicker` (task 1, owner approved). Do not add any other package. Do not add Avalonia.Headless.
- Follow `.claude/rules/` (`csharp.md`, `avalonia-mvvm.md`, `localization.md`, `testing-and-quality.md`): compiled bindings with `x:DataType`, no Avalonia types in view models or `Workspace/`, one type per file, `internal` types in App, no hardcoded colors in views, avoid the word "kind" when "type" works. Keep the build warning-free (warnings are errors). Test classes are public, so internal enums and structs must not appear as parameters of public test methods (use loops inside facts instead of theories for them).
- Translatable texts: `ILocalizer.T("English")` in C#, `Localizer.N("English")` in tables, `{loc:T 'English'}` in XAML. Every new text goes into `Translations/de.po` in the same task, and removed texts are removed from it, because `TranslationConsistencyTests` fail on missing or obsolete entries.
- Tests: xUnit, `Method_Scenario_Expected`, arrange/act/assert, deterministic (inject id sources and so on). Existing tests that break because of a task are updated in that task. Search `.spec-workflow/specs/*/Implementation Logs/` before writing code.
- Only `EditorState` assigns the document in production code (`AppArchitectureTests`). Edits use `Edit`, drags use `Preview` and `Commit`, a new document uses `ReplaceDocument`.
- If anything is unclear or the design does not work, stop and ask the owner. Do not guess. If a task cannot build without another one, say so and do them together, and log them separately.
- For manual runs read the memory notes: move the app window to the right screen after launch, re-read its position before each batch of input, use a separate `XDG_CONFIG_HOME` and scratchpad folders, and remove any temporary code afterwards.
- Build and test: `dotnet build src/PressToShape.Desktop`, `dotnet test`, and `dotnet format --verify-no-changes`.
- Do not commit unless the owner asks.
